Adapté mi guía de Windows por red con iPXE a UEFI y a Proxmox VE. La guía original genera bin/ipxe.usb, que es BIOS Legacy; acá hay que compilar bin-x86_64-efi/ipxe.efi y ponerlo en una partición ESP FAT32 como EFI/BOOT/BOOTX64.EFI.

Otro cambio importante: el servidor HTTP tiene que soportar peticiones Range. Con python3 -m http.server iPXE no pudo cargar el ISO y mostró «no se puede cargar el ISO». Con nginx, que responde 206 Partial Content, arrancó sin problemas.

1. Datos de esta instalación

Servidor Arch: 192.168.0.201 (interfaz wlp1s0, conectada a la misma LAN que la PC destino).

ISO utilizada: proxmox-ve_9.2-1.iso.

http://download.proxmox.com/iso/proxmox-ve_9.2-1.iso
sha256: 4e88fe416df9b527624a175f24c9aa07c714d3332afb1ee3dbf3879573ef2c6c

Rutas del servidor:

/srv/pxe/proxmox-ve_9.2-1.iso
/srv/pxe/boot.ipxe
/etc/nginx/nginx.conf
/etc/dnsmasq-pxe.conf

2. Descargar y verificar el ISO

sudo mkdir -p /srv/pxe
sudo wget -c -O /srv/pxe/proxmox-ve_9.2-1.iso \
  http://download.proxmox.com/iso/proxmox-ve_9.2-1.iso

echo '4e88fe416df9b527624a175f24c9aa07c714d3332afb1ee3dbf3879573ef2c6c  /srv/pxe/proxmox-ve_9.2-1.iso' | sha256sum -c -

El ISO pesa unos 1,7 GB, así que conviene dejar espacio libre en /.

3. Servidor HTTP con nginx

Instalar nginx:

sudo pacman -S --needed nginx

Configuración mínima en /etc/nginx/nginx.conf:

worker_processes 1;
events {
    worker_connections 1024;
}
http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;
    server {
        listen 80;
        server_name _;
        root /srv/pxe;
        autoindex on;
    }
}

Arrancar y verificar:

sudo systemctl enable --now nginx
curl -I http://127.0.0.1/boot.ipxe

curl -H 'Range: bytes=0-1023' -o /dev/null \
  -w 'code=%{http_code} size=%{size_download}\n' \
  http://127.0.0.1/proxmox-ve_9.2-1.iso

Tiene que devolver code=206 size=1024. Si devuelve 200 y el tamaño completo, iPXE no va a poder arrancar el ISO.

4. Script iPXE del servidor

/srv/pxe/boot.ipxe:

#!ipxe
:start
menu Proxmox VE 9.2 - servidor 192.168.0.201
item --default proxmox Instalar Proxmox VE 9.2 (ISO completa)
item shell Ir a shell iPXE
item exit Salir / siguiente dispositivo
choose --default proxmox --timeout 15000 target && goto ${target}

:proxmox
echo Arrancando instalador de Proxmox VE 9.2...
sanboot http://192.168.0.201/proxmox-ve_9.2-1.iso || goto failed

:shell
shell
goto start

:exit
exit

:failed
echo ERROR: no se pudo arrancar el ISO.
sleep 10
goto start

Probar:

curl -I http://127.0.0.1/boot.ipxe
curl -I http://127.0.0.1/proxmox-ve_9.2-1.iso

5. Proxy DHCP opcional

Esto no asigna direcciones IP, solo anuncia el archivo de arranque para que un iPXE ya cargado pueda encadenar automáticamente. Lo hace dnsmasq en /etc/dnsmasq-pxe.conf:

interface=wlp1s0
bind-interfaces
port=0
dhcp-range=192.168.0.0,proxy
dhcp-boot=tag:ipxe,http://192.168.0.201/boot.ipxe
log-facility=/srv/pxe/dnsmasq.log

sudo dnsmasq -C /etc/dnsmasq-pxe.conf

Ajustá interface según tu máquina. Si el pendrive no encadena solo, siempre se puede escribir en el prompt de iPXE:

dhcp
chain http://192.168.0.201/boot.ipxe

6. Compilar iPXE UEFI con script integrado

El script embebido evita que iPXE termine en Nothing to boot después de obtener DHCP.

git clone --depth=1 https://github.com/ipxe/ipxe.git /tmp/ipxe
cd /tmp/ipxe/src

/tmp/ipxe/src/boot.ipxe:

#!ipxe
dhcp
chain http://192.168.0.201/boot.ipxe

make bin-x86_64-efi/ipxe.efi EMBED=boot.ipxe -j$(nproc)
file bin-x86_64-efi/ipxe.efi

El resultado tiene que ser un PE32+ executable for EFI (application), x86-64.

7. Grabar el pendrive en modo UEFI

Esto borra por completo el dispositivo elegido. Identificá el pendrive con lsblk; no adivines el nombre. En este caso era /dev/sdb, modelo DataTraveler 2.0, de 1,9 GB.

lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINTS,RM

Solo si confirmaste el dispositivo:

sudo parted -s /dev/sdb mklabel gpt
sudo parted -s /dev/sdb mkpart ESP fat32 1MiB 100%
sudo parted -s /dev/sdb set 1 esp on
sudo mkfs.vfat -F32 -n IPXE_UEFI /dev/sdb1

sudo mkdir -p /mnt/ipxeusb/EFI/BOOT
sudo mount /dev/sdb1 /mnt/ipxeusb
sudo cp /tmp/ipxe/src/bin-x86_64-efi/ipxe.efi /mnt/ipxeusb/EFI/BOOT/BOOTX64.EFI
sudo cp /tmp/ipxe/src/bin-x86_64-efi/ipxe.efi /mnt/ipxeusb/ipxe.efi
sync
sudo umount /mnt/ipxeusb

El archivo clave es /EFI/BOOT/BOOTX64.EFI: es la ruta de fallback que busca el firmware UEFI en una partición FAT32.

8. Arrancar la PC destino

Conectar la PC destino por Ethernet a la misma LAN del servidor, entrar al menú de arranque UEFI y elegir el pendrive.

Si el firmware tiene Secure Boot activado, hay que desactivarlo: el ipxe.efi compilado acá no está firmado.

Si la PC es UEFI de 32 bits, hace falta compilar también bin-i386-efi/ipxe.efi y copiarlo como EFI/BOOT/BOOTIA32.EFI.

9. El error «no se puede cargar el ISO»

Apareció este mensaje desde el menú de iPXE:

ERROR: no se pudo arrancar el ISO.

La causa fue el servidor HTTP: python3 -m http.server ignora la cabecera Range, así que iPXE no podía leer el ISO como dispositivo de bloque. El log mostraba muchos GET /proxmox-ve_9.2-1.iso y BrokenPipeError.

La solución fue reemplazarlo por nginx y confirmar que responda 206 Partial Content:

curl -H 'Range: bytes=0-1023' -o /dev/null \
  -w 'code=%{http_code} size=%{size_download}\n' \
  http://192.168.0.201/proxmox-ve_9.2-1.iso

Después de eso, sanboot http://192.168.0.201/proxmox-ve_9.2-1.iso cargó el ISO y abrió el instalador de Proxmox VE 9.2.

Los BrokenPipeError que siguen apareciendo en el log de nginx son normales: iPXE corta la conexión cuando entrega el arranque al instalador.

10. Después del arranque

Dentro del instalador de Proxmox:

  1. Aceptar la licencia y elegir el disco destino (se borra por completo; por defecto ZFS).
  2. Configurar zona horaria, teclado, contraseña de root y email.
  3. En red, poner IP fija (por ejemplo 192.168.0.202/24, gateway 192.168.0.1) o DHCP.
  4. Confirmar e instalar. Al reiniciar, sacar el pendrive y entrar a https://<esa-IP>:8006.

Resultado

El pendrive con iPXE UEFI arranca desde la PC destino, encadena con http://192.168.0.201/boot.ipxe y carga el ISO completo de Proxmox VE 9.2 servido por nginx en la misma LAN. El pendrive se usa solamente para arrancar iPXE; todo el instalador viene por red.
