Google Antigravity CLI: mi alternativa favorita

Plan gratuito

Agente autónomo de terminal

Google reemplazó el acceso gratuito individual de Gemini CLI por Antigravity CLI el 18 de junio de 2026. Es importante porque muchos tutoriales todavía recomiendan el viejo Gemini CLI.

image

Antigravity es malo usa copilot, opencode, gemcli, freebuff, sengptr, wtagent, portal

y este:

xvfb-run --auto-servernum --server-args="-screen 0 1280x900x24" wtagent

Antigravity permite ejecutar tareas de programación y utilizar herramientas desde la terminal, con un plan de $0 y cuotas limitadas.

En Arch Linux:

curl -fsSL https://antigravity.google/cli/install.sh -o /tmp/agy-install.sh
less /tmp/agy-install.sh
bash /tmp/agy-install.sh

Luego:

~/.local/bin/agy

Te pedirá iniciar sesión con Google. Es una alternativa genuina a Claude Code, aunque necesita autenticación y está sujeta a límites gratuitos.

¿Cómo extender tus créditos sin pagar?

No encontré un método oficial para aumentar ilimitadamente los créditos de Big Pickle. La estrategia práctica es combinar cuotas independientes: OpenCode gratuito, Antigravity Free y Copilot Free.

También podés reducir el consumo usando conversaciones nuevas para tareas distintas y evitando mandar repositorios completos cuando solo necesitás modificar unos archivos.

Y algo importante: los modelos gratuitos locales con Ollama no tienen cuotas, pero en una máquina con 4 GB de RAM difícilmente consigas un agente comparable a Claude Code para tareas complejas.

Mi recomendación: conservá OpenCode como agente principal, probá GLM-5.3 Flash y DeepSeek V4.1 Flash, e instalá Antigravity CLI como segundo agente. Así tenés dos servicios distintos para seguir trabajando cuando uno alcance su límite, sin pagar suscripciones.


#!/usr/bin/env bash
# Borra las credenciales de la cuenta de Google de Antigravity CLI (agy)
# sin tocar el historial de conversaciones.
#
# Uso:
#   agy-borrar-cuenta              # pide confirmación
#   agy-borrar-cuenta --si         # sin preguntar (yes)
#   agy-borrar-cuenta --dry-run    # solo muestra qué haría
#
# Qué borra:  ~/.gemini/antigravity-cli/antigravity-oauth-token
# Qué conserva: conversations/, brain/, history.jsonl,
#               conversation_summaries.db, settings.json, proyectos, MCP...
#
# Después de ejecutarlo tendrás que volver a iniciar sesión al abrir `agy`.

set -uo pipefail

CONFIG_DIR="${AGY_CONFIG_DIR:-$HOME/.gemini/antigravity-cli}"

# Archivos que contienen credenciales/identidad de la cuenta de Google.
# (Si en el futuro Antigravity añade más, se agregan aquí.)
ARCHIVOS_CUENTA=(
  "$CONFIG_DIR/antigravity-oauth-token"
)

# Rutas que NUNCA se deben tocar (historial).
HISTORIAL=(
  "$CONFIG_DIR/conversations"
  "$CONFIG_DIR/brain"
  "$CONFIG_DIR/history.jsonl"
  "$CONFIG_DIR/conversation_summaries.db"
)

DRY_RUN=0
ASUMIR_SI=0

for arg in "$@"; do
  case "$arg" in
    --dry-run|-n) DRY_RUN=1 ;;
    --si|--yes|-y) ASUMIR_SI=1 ;;
    -h|--help)
      sed -n '2,14p' "$0" | sed 's/^# \{0,1\}//'
      exit 0
      ;;
    *)
      echo "Opción desconocida: $arg (usa --help)" >&2
      exit 2
      ;;
  esac
done

if [[ ! -d "$CONFIG_DIR" ]]; then
  echo "No existe $CONFIG_DIR — ¿está instalado Antigravity CLI?" >&2
  exit 1
fi

# Inventario previo del historial, para comprobar que no se toca.
historial_antes=$(
  find "${HISTORIAL[@]}" -type f 2>/dev/null | wc -l
)

existentes=()
for f in "${ARCHIVOS_CUENTA[@]}"; do
  [[ -e "$f" ]] && existentes+=("$f")
done

if [[ ${#existentes[@]} -eq 0 ]]; then
  echo "No hay archivos de cuenta que borrar en $CONFIG_DIR."
  echo "Parece que ya no hay sesión de Google guardada."
  exit 0
fi

echo "Se van a borrar (credenciales de la cuenta):"
printf '  - %s\n' "${existentes[@]}"
echo
echo "Se conserva (historial y ajustes):"
printf '  - %s\n' "${HISTORIAL[@]}"
echo

if [[ $DRY_RUN -eq 1 ]]; then
  echo "[dry-run] No se borró nada."
  exit 0
fi

if [[ $ASUMIR_SI -eq 0 ]]; then
  read -r -p "¿Borrar la cuenta guardada? [s/N] " resp
  case "$resp" in
    s|S|si|Si|SI|y|Y|yes) ;;
    *) echo "Cancelado."; exit 0 ;;
  esac
fi

borrado_ok=1
for f in "${existentes[@]}"; do
  if command -v shred >/dev/null 2>&1; then
    shred -u -- "$f" || { echo "ERROR: no se pudo borrar $f" >&2; borrado_ok=0; }
  else
    rm -f -- "$f" || { echo "ERROR: no se pudo borrar $f" >&2; borrado_ok=0; }
  fi
  [[ -e "$f" ]] && { echo "ERROR: $f sigue existiendo" >&2; borrado_ok=0; }
done

historial_despues=$(
  find "${HISTORIAL[@]}" -type f 2>/dev/null | wc -l
)

echo
if [[ $borrado_ok -eq 1 ]]; then
  echo "Credenciales de la cuenta borradas."
else
  echo "Hubo errores al borrar (ver arriba)." >&2
fi

if [[ "$historial_antes" -eq "$historial_despues" ]]; then
  echo "Historial intacto: $historial_despues archivos."
else
  echo "AVISO: el número de archivos de historial cambió ($historial_antes → $historial_despues)." >&2
fi

echo "La próxima vez que abras 'agy' tendrás que iniciar sesión de nuevo."

# Aviso: el email de la cuenta puede aparecer dentro del historial
# (transcripciones). Eso NO se toca aquí porque pediste conservarlo.
exit $(( borrado_ok == 1 ? 0 : 1 ))

5. ChatGPT / Codex con OAuth: sin API key y sin pagar

OpenAI también se puede usar sin API key: la cuenta de ChatGPT permite autenticarse por OAuth y el proyecto openai-oauth expone una API compatible con OpenAI. OpenCode se conecta como si fuera un proveedor normal, con tool calls nativos.

Requisitos

  • Una cuenta de ChatGPT (el plan free alcanza, pero el cupo es chico).
  • Node.js y npm.
  • Un navegador para autorizar una sola vez.

Instalación

mkdir -p ~/openai-oauth
cd ~/openai-oauth
npm init -y
npm install openai-oauth@2.0.0
npx openai-oauth@2.0.0 login

Si la máquina es headless (sin entorno gráfico), usá:

npx openai-oauth@2.0.0 login --no-open

Te va a imprimir una URL de auth.openai.com. Abrila en cualquier navegador donde ya tengas la sesión de ChatGPT, elegí la cuenta, aceptá el consentimiento de Codex y listo. El callback vuelve a http://localhost:1455/auth/callback y las credenciales quedan en:

~/.codex/auth.json   # permisos 600

Levantar el proxy

npx openai-oauth@2.0.0 --host 127.0.0.1 --port 10531

Eso expone:

http://127.0.0.1:10531/v1

con endpoints compatibles con OpenAI (/v1/models, /v1/chat/completions, /v1/responses).

Servicio systemd (opcional)

Para que arranque solo:

# ~/.config/systemd/user/openai-oauth.service
[Unit]
Description=OpenAI OAuth proxy
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/openai-oauth
ExecStart=/usr/bin/node %h/openai-oauth/node_modules/openai-oauth/dist/cli.js --host 127.0.0.1 --port 10531
Restart=always
RestartSec=3

[Install]
WantedBy=default.target

systemctl --user daemon-reload
systemctl --user enable --now openai-oauth.service
systemctl --user status openai-oauth.service

Configurar OpenCode

En ~/.config/opencode/opencode.json:

{
  "providers": {
    "chatgpt-oauth": {
      "name": "ChatGPT (OAuth)",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:10531/v1",
        "apiKey": "dummy"
      },
      "models": {
        "gpt-6-luna": {
          "name": "GPT-6 Luna",
          "capabilities": { "tools": true, "input": ["text", "image"], "output": ["text"] },
          "limit": { "context": 500000, "output": 32768 }
        },
        "gpt-5.6-terra": {
          "name": "GPT-5.6 Terra",
          "capabilities": { "tools": true, "input": ["text", "image"], "output": ["text"] },
          "limit": { "context": 272000, "output": 32768 }
        },
        "gpt-5.6-luna": {
          "name": "GPT-5.6 Luna",
          "capabilities": { "tools": true, "input": ["text", "image"], "output": ["text"] },
          "limit": { "context": 272000, "output": 32768 }
        }
      }
    }
  }
}

El apiKey: "dummy" es solo para que el cliente OpenAI-compatible no se queje; el proxy lo ignora.

Después abrís OpenCode, /models → ChatGPT (OAuth) → GPT-6 Luna.

Si el proxy corre en otra máquina

Dejalo escuchando en 127.0.0.1 y llevá el puerto por SSH:

ssh -N -L 127.0.0.1:10531:127.0.0.1:10531 usuario@otra-maquina

Así no lo exponés a la LAN.

Aviso importante: el plan free tiene poco cupo

El plan free de ChatGPT incluye acceso a Codex, pero con un cupo muy chico. No es para uso intensivo: dos o tres pedidos con tool calls pueden agotarlo. No te cobran nada, simplemente se corta hasta que resetee. El cupo se comparte con Codex CLI/IDE.

Para no gastarlo en tareas de mantenimiento, podés hacer que los agentes internos de OpenCode usen un modelo gratis:

"agents": {
  "title": { "model": "opencode/big-pickle" },
  "summary": { "model": "opencode/big-pickle" },
  "compaction": { "model": "opencode/big-pickle" }
}

Así los títulos, resúmenes y la compactación no consumen el cupo de ChatGPT.

Antigravity no tiene, hasta donde probé, una API compatible con OpenAI, así que no se puede enchufar a OpenCode como proveedor. La estrategia es usarlo como segundo agente cuando OpenCode se queda sin cuota.

Estrategia para no pagar

  1. Día a día: los modelos gratis de OpenCode (big-pickle, flint-40b-free, GLM-5.3 Flash, DeepSeek V4.1 Flash).
  2. Segundo agente: Antigravity (agy) con Gemini 3.8 Flash o Claude Sonnet 4.6.
  3. Tercer agente: GitHub Copilot Free.
  4. ChatGPT/Codex: solo para lo difícil, porque el cupo free es chico.
  5. Ahorro extra: usá conversaciones nuevas para tareas distintas, no mandes repos completos y configurá agents.title/summary/compaction con un modelo gratis.

Ninguno de estos métodos es oficial ni está garantizado: OpenAI, Google y GitHub pueden cambiar los límites, los modelos o el acceso cuando quieran. La ventaja es que no hay tarjeta ni factura: si se termina la cuota, esperás o cambiás de agente.

Opción adicional que no estaba en la lista:

OmniRoute: gateway MIT con un solo endpoint que soporta 22+ proveedores vía cookies web (ChatGPT, Claude, Gemini, DeepSeek, Grok, Copilot, HuggingChat, etc.) y 375+ proveedores en total. Funciona como proxy compatible con OpenAI, así que se integra con Claude Code, Codex, Cursor, Cline, Copilot, etc. Comprime tokens con RTK+Caveman (ahorro 15-95%). Es probablemente la opción más versátil si ya usás algún agente de código y querés redirigirlo a tu cuenta web. Sobre ask-gemini: no logré confirmarlo en PyPI ni GitHub con ese nombre exacto. Lo que sí existe y hace lo mismo es gemini-web-cli (escrito en Go), que importa las cookies __Secure-1PSID y __Secure-1PSIDTS, tiene modo interactivo, lista chats y hasta expone un servidor REST compatible con OpenAI + endpoint MCP.

Riesgo concreto que vale la pena mencionar: estos proyectos rompen cada vez que el proveedor cambia el HTML, los nombres de cookies o la estructura de la página. Sengpt original murió por eso. Sengptr y WTAgent son forks mantenidos precisamente para resolverlo, pero no hay garantía de que sigan funcionando. Usá siempre una cuenta secundaria.

Sí, existe un “hack” equivalente a GemCLI pero para Brave Leo: se llama @eliyantosarage/leo-cli y lleva la IA de Brave (la que ves en chrome://leo-ai) a la terminal usando automatización del navegador vía Playwright + CDP.

🦁 Leo CLI (Brave Leo en la terminal)

Instalación

npm i -g @eliyantosarage/leo-cli
leo doctor          # verifica que Brave, CDP y Playwright estén OK

Requisitos: Node.js ≥18 y Brave Browser instalado (Stable o Beta).

Autenticación (una sola vez) La primera vez que ejecutes leo o leo ask, la herramienta abrirá Brave para capturar tu sesión de Leo y guardará las credenciales en ~/.leo-cli/cache/leo-auth.json. Después ya puedes usarlo sin tener Brave abierto:

leo ask --transport direct "tu pregunta"

O forzar una captura fresca por prompt (abre Brave un segundo y lo cierra):

leo ask --transport mitm "tu pregunta"

Uso como agente (lo importante)

leo agent "revisa este proyecto y sugiere mejoras"

El modo agent tiene tool calling estilo Claude Code: leer/escribir archivos, ejecutar comandos de shell, buscar código (Grep/Glob), fetch de URLs, gestión de tareas y subagentes.

Chat interactivo

leo chat
# o con TUI experimental:
leo chat --tui

Ver modelos disponibles

leo models

Soporta varios modelos de Leo (automático, Qwen, Mistral, DeepSeek, etc.).

🧠 Cómo funciona el “truco”

Leo CLI no usa una API key: automatiza el navegador. Escribe tu prompt en el input de Leo (data-testid="leo-input"), pulsa el botón de enviar y espera a que el DOM se estabilice para extraer la respuesta final. Por eso necesita Brave instalado y una sesión de Leo activa (aunque sea la capa gratuita).

⚠️ Alternativas que quizás veas por ahí

  • tgpt: es más simple y también lista “Brave Leo” como proveedor, pero no es un agente: no tiene tool calling ni puede editar archivos. Es solo chat.
  • @brave/bravebot: es un agente oficial de Brave, pero no es un hack de sesión web; se instala como un agente general y probablemente requiera su propia configuración/API, no reutiliza tu sesión de Leo del navegador.

🎯 Recomendación

Si lo que te gustó de GemCLI fue reutilizar tu sesión web y tener herramientas de agente, leo-cli es la opción directa para Brave. Instálalo, ejecuta leo doctor para confirmar que todo está en orden, y prueba primero con leo ask antes de lanzarte al modo leo agent.

Eso sí: como todo este tipo de herramientas, no es oficial y puede dejar de funcionar si Brave cambia la interfaz de Leo. Úsalo con una cuenta que no sea crítica y revisa que el paquete sea el correcto (@eliyantosarage/leo-cli) antes de instalarlo.

Sí, el ecosistema de “hacks de sesión web” es bastante amplio. Te los agrupo por capacidad real de agente (los que pueden editar archivos y ejecutar comandos) y por proveedor, con los comandos de instalación y uso.

🧠 Agentes autónomos que usan tu sesión web (los más parecidos a GemCLI en capacidades)

ClaudeCode-Next (Claude) Es probablemente el más directo: usa la interfaz web de Claude.ai, extrae tu sesión una vez y funciona como agente completo desde la terminal (lee/escribe archivos, ejecuta comandos, refactoriza, modo agente interactivo).

pip install "claudecode-next[browser]"
playwright install chromium

claudecode-next --auto-fetch        # importa cookies de Chrome
claudecode-next --agent "Refactoriza utils.py para usar pathlib"
claudecode-next --prompt "Explica este error"

También tiene --login (abre navegador) y --manual (pegar cookies a mano).

Dulus (Gemini por defecto, también Claude y GPT) Runtime de agente en Python que arranca capturando una sesión anónima de Gemini sin API key ni cuenta. Tiene CLI, GUI, web y Telegram, y puede ejecutar comandos bash en tu terminal.

pip install dulus
dulus

Para otros proveedores, dentro del runtime puedes cambiar a Claude o GPT (siempre que tengas sesión web iniciada en el navegador).

🌐 Multi‑proveedor (varios modelos desde una sola herramienta)

surf-cli Controla tu Chrome real mediante una extensión y permite consultar ChatGPT, Gemini, Perplexity y Grok usando tus logins del navegador, sin API keys. No es un agente autónomo por sí mismo, pero está pensado para que agentes como Claude Code o Cursor lo usen como “herramienta de navegador”.

npm install -g surf-cli
# Instalar la extensión en Chrome (Developer mode → Load unpacked → ruta que imprime:)
surf extension-path
surf install <extension-id>

Uso:

surf go "https://chatgpt.com"
surf read
# O consultas directas:
surf ask chatgpt "resume este error"

mcp-ai-router Servidor MCP (stdio) que automatiza sesiones web autenticadas de Gemini, ChatGPT, Claude, DeepSeek y Kimi mediante un Chromium propio (CloakBrowser). No es un agente, pero cualquier cliente MCP (Claude Code, Cursor, Claude Desktop) puede usarlo como proveedor de modelos.

pipx install mcp-ai-router
ai-router browser login          # abre ventanas para loguearte una vez
ai-router browser status         # verifica que estén "logged_in"

Luego lo añades a tu cliente MCP:

{
  "mcpServers": {
    "ai-router": { "command": "ai-router", "args": ["serve"] }
  }
}

WebModel Bridge Proxy local que convierte 9 webs de IA (Claude, ChatGPT, DeepSeek, Gemini, Grok, Perplexity, Kimi, Qwen, GLM) en una API compatible con OpenAI y Anthropic. Usa Chrome real vía CDP, heredando cookies y fingerprint. No es un agente, pero permite que Cursor, Claude Code o cualquier cliente OpenAI apunten a http://localhost:3456 y usen esas webs gratis.

# (Requiere Node 20+ y Chrome corriendo con remote debugging)
git clone https://github.com/.../webmodel-bridge
cd webmodel-bridge
npm install
npm start

Luego en tu cliente OpenAI:

baseURL: http://localhost:3456/v1
apiKey: dummy

llm-cookie-bridge (Python) Librería, no CLI. Da una interfaz async única para hablar con Gemini, ChatGPT, Claude, Perplexity, HuggingFace Chat, Grok, Phind, DeepSeek, You.com, Pi.ai, Meta AI, Mistral Le Chat y Copilot usando cookies de sesión. Útil si quieres construir tu propio agente sin depender de un CLI ya hecho.

pip install llm-cookie-bridge

Uso mínimo (ejemplo con ChatGPT):

from llm_cookie_bridge import LLMCookieBridge
bridge = LLMCookieBridge.create("chatgpt", cookies={"__Secure-next-auth.session-token": "..."})

💬 CLI de consulta/chat por proveedor (sin tool calling)

Hajimi (Gemini) CLI + servidor MCP para Gemini Web. Pide tus cookies __Secure-1PSID y __Secure-1PSIDTS (las sacas de DevTools) o las detecta desde un archivo. Tiene generación de texto, imágenes, análisis de archivos y sesiones persistentes, pero no tool calling (no edita archivos por sí solo).

git clone https://github.com/ssttkkl/hajimi
cd hajimi
uv sync
gemini-web auth setup
gemini-web generate "Hola"

gemini-web-cli (Gemini) CLI + modo OpenAI-compatible + MCP. Permite conversación, generación de imágenes/vídeo/música, Deep Research y Notebook. No soporta tool call, así que es para consultas y automatización, no para agente autónomo de código.

# Instalación según el repo (Leechael/gemini-web-cli)
gemini-web-cli ask "Explain quantum computing"
gemini-web-cli serve --port 8080   # API OpenAI-compatible

ask-gemini (Gemini) CLI ligero que detecta automáticamente cookies de Chrome o Edge. Solo chat, sin herramientas.

pip install ask-gemini
ask-gemini "Hola"
ask-gemini --chat

chatgpt-web-mcp (ChatGPT) Servidor MCP que usa Playwright y cookies de ChatGPT. No es agente autónomo, pero lo puedes conectar a Claude Desktop/Cursor como herramienta de consulta.

npx -y chatgpt-web-mcp setup        # login interactivo
# Luego configuras el MCP server en tu cliente

xse-chat (ChatGPT) CLI de chat vía Puppeteer. Exportas cookies de ChatGPT a cookies/chatgpt.json con una extensión tipo EditThisCookie y luego consultas desde terminal.

swift-grok (Grok) CLI para Grok que genera credenciales desde cookies de grok.com (grok auth). Ojo: el CLI requiere macOS 14+, así que en tu Arch Linux no te sirve directamente. Para Linux, usa Grok a través de surf-cli, mcp-ai-router o WebModel Bridge.

📋 Multi‑proveedor “navaja suiza”

@vk007/mikacli No es un agente LLM, pero es una herramienta de automatización que maneja 120 proveedores (incluyendo LLMs, GitHub, Google, etc.) reutilizando sesiones de navegador guardadas. Puede consultar ChatGPT, Qwen y otros desde la terminal con --json para que agentes lo usen.

npm install -g @vk007/mikacli
mikacli login --browser
mikacli llm chatgpt text "Write release notes"

⚠️ Lo que debes tener en cuenta con todos estos

  • No son oficiales: la mayoría extrae cookies o automatiza la web, lo que puede violar los Términos de Servicio del proveedor y romperse cuando cambien la interfaz.
  • Seguridad de las cookies: si una herramienta te pide tus cookies de sesión, trátalas como contraseñas. Usa una cuenta que no sea crítica y revisa que el paquete sea el correcto antes de instalarlo.
  • Caducidad: las cookies de ChatGPT suelen durar 30–90 días; las de Claude y Gemini, menos. Cuando falle la autenticación, tendrás que volver a hacer el login.
  • Tool calling real: si lo que buscas es que el agente edite archivos y ejecute comandos (como GemCLI), las opciones más directas de esta lista son ClaudeCode-Next y Dulus. El resto son más bien puentes para consultar modelos o para que otros agentes los usen como herramienta.

Sí, existen bastantes proyectos con la misma filosofía que GemCLI: reutilizar la sesión web que ya tienes iniciada en el navegador para usarla como agente de terminal, sin pasar por la API oficial ni pagar por token.

La mecánica suele ser la misma: la herramienta abre un perfil de Chrome/Chromium dedicado (o importa tus cookies) donde ya estás logueado, y desde ahí opera la interfaz web del asistente. Por eso venían funcionando opciones como GemCLI, y por eso hay alternativas equivalentes para otros modelos.

🧠 Para ChatGPT

  • Sengptr: es un fork mantenido de Sengpt. Corre ChatGPT en un perfil de Chromium dedicado y permite conversaciones interactivas, prompts de una sola vez o pipear archivos directamente desde la terminal.

    pip install sengptr
sengptr --login   # primera vez, abre Chromium para el login
sengptr "explica este error de compilación"

  • WTAgent: CLI open-source (MIT) que convierte tu cuenta web de ChatGPT en un agente estilo Codex. Lee archivos del proyecto, planifica cambios, edita y ejecuta comandos/tests. También soporta Claude, Gemini, DeepSeek, Grok, Kimi y GLM con el flag --model.

    npm i -g wtagent
wtagent
# dentro, o con:
wtagent --model claude

  • chatferry: CLI que permite hablar con ChatGPT y Claude usando tus propias sesiones del navegador, sin API keys.

🧠 Para Claude

  • claudecode-next: agente de código no oficial que corre sobre la interfaz web de Claude.ai. Lee/escribe archivos, ejecuta comandos, busca y refactoriza código, y tiene modo agente autónomo. Extrae la sesión de tu navegador una vez y luego funciona completamente desde la CLI.

    pip install claudecode-next
claudecode-next --auto-fetch   # importa cookies de Chrome
claudecode-next --agent "Refactoriza utils.py para usar pathlib"

  • WTAgent también cubre Claude (wtagent --model claude), como vimos arriba.

🧠 Para Gemini (además de GemCLI)

  • ask-gemini: CLI que habla con la interfaz web de Gemini. No necesita API key: detecta automáticamente las cookies de Chrome o Edge, o permite configurarlas manualmente (__Secure-1PSID y __Secure-1PSIDTS). Tiene modo chat interactivo, sesiones con nombre y puede reanudar conversaciones que ya tengas abiertas en la web. 
    pip install ask-gemini
ask-gemini "Hola"
ask-gemini --chat   # modo interactivo

🌐 Multi-proveedor (varios modelos en una sola herramienta)

  • Portal (@kabxx/portal): es probablemente la alternativa más directa y completa a GemCLI. Lanza un Chromium real y maneja ChatGPT, Gemini, DeepSeek, Doubao, Grok, GLM, Qwen y Kimi desde una sola TUI. Soporta herramientas locales (comandos, parches de archivos, imágenes), login persistente y ejecución headless con portal exec.

    npm install --global @kabxx/portal@latest
portal
# dentro:
/thread agent chatgpt

    O para una tarea puntual:

    portal exec --provider chatgpt "Resume este repositorio"

  • OpenClaw Zero Token: fork de OpenClaw centrado en eliminar el coste de tokens. Te logueas una vez en el navegador y luego llama a ChatGPT, Claude, Gemini, DeepSeek, Qwen, GLM, Manus y otros a través de una puerta de enlace unificada.

⚠️ Lo que debes tener en cuenta antes de probar

Este tipo de herramientas no son oficiales. En la mayoría de los casos sus propios autores advierten que pueden violar los Términos de Servicio del proveedor y que pueden dejar de funcionar en cualquier momento si cambian la web o los mecanismos de autenticación.

También hay un riesgo de seguridad: para funcionar necesitan acceso a tus cookies de sesión, y algunas herramientas piden permisos amplios sobre el navegador. Si vas a probarlas, conviene hacerlo con una cuenta que no sea crítica y revisar qué hace exactamente el binario o el paquete antes de darle acceso.

Dicho esto, Portal es la que más se parece a lo que ya te gustó de GemCLI: una sola interfaz, varios modelos y herramientas de agente reales sin API key. Si quieres probar otra, empezaría por ahí.

Exacto, SenGPTR es solo un puente de chat: te permite hablar con el modelo a través de tu sesión web, pero no tiene la capacidad de actuar sobre tu sistema. Para que un modelo web (como ChatGPT o Gemini) tome el control de tu PC, necesitas una capa adicional que le proporcione “herramientas” (tool calling) para leer archivos, escribir código y ejecutar comandos en tu terminal.

La buena noticia es que existen varias herramientas que hacen exactamente eso, usando tu sesión del navegador como backend. Aquí tienes las opciones más directas, ordenadas de la más sencilla a la más potente.

🥇 Portal: la opción más directa y completa

Portal es probablemente la herramienta que mejor se adapta a lo que buscas. Lanza un Chromium real, se conecta a la web de ChatGPT (o Gemini, DeepSeek, etc.) usando tu sesión ya iniciada, y le otorga herramientas locales para que el modelo pueda ejecutar comandos, aplicar parches a archivos y trabajar de forma autónoma.

Instalación:

npm install --global @kabxx/portal@latest

Uso (modo interactivo):

portal

Dentro de la TUI, creas un hilo de agente y le das una tarea:

/thread agent chatgpt
Resume este repositorio e identifica el módulo de mayor riesgo.

Uso (tarea única, sin TUI):

portal exec --provider chatgpt "Resume este repositorio."

Portal soporta ChatGPT, Gemini, DeepSeek, Doubao, Grok, GLM, Qwen y Kimi. Es la opción más “todo-terreno”.

🥈 CatDesk: ChatGPT Web como agente de código

CatDesk convierte la web de ChatGPT en un agente de codificación completo. Funciona como un servidor MCP local que le da a ChatGPT Web las herramientas write y run_command para editar archivos y ejecutar comandos en tu máquina.

Instalación:

npm install -g catdesk

Uso:

catdesk

(Requiere una suscripción de ChatGPT Plus o superior para usar la función de “Custom Connector” que conecta la web con el servidor local).

⚠️ Advertencia importante: El propio autor de CatDesk recomienda encarecidamente ejecutarlo dentro de una VM o contenedor (como DevContainer), porque el agente tiene permisos para borrar discos o causar daños inesperados.

🥉 Forge Agent: agente autónomo multi-modelo

Forge Agent es un agente de codificación autónomo que funciona con DeepSeek, ChatGPT o Gemini a través de la automatización del navegador. No necesita API key y está diseñado para leer archivos, escribir código, ejecutar comandos y repetir el bucle hasta terminar la tarea.

Instalación:

npm install -g forge-agent
# o el alias corto:
npm install -g @omar-azam/forge-agent

Uso:

# Tarea única
forge "construye una API REST con Express y JWT"

# Modo interactivo (múltiples tareas con contexto compartido)
forge --interactive

# Especificar modelo
forge --model=gemini "escribe tests unitarios para auth.js"

# Ver el plan antes de ejecutar
forge --plan "migra esta app a TypeScript"

Forge incluye 37+ herramientas integradas (I/O de archivos, shell, git, búsqueda, tests, paquetes, etc.) y perfiles de agente preconfigurados (backend, frontend, data-science, devops).

🔧 Otras alternativas específicas

Dulus (para Gemini) Si prefieres usar Gemini en lugar de ChatGPT, Dulus es un runtime de agente que captura tu sesión web (incluso la anónima, sin login) y la convierte en un agente con tool calling: lee y edita archivos, ejecuta Bash, busca en tu repo y hace commits.

pip install -U dulus
dulus
# o con el instalador:
curl -fsSL https://raw.githubusercontent.com/KevRojo/Dulus/main/install.sh | bash

chatgpt-browser-agent Es un daemon de navegador persistente + servidor MCP + bucle de agente. Permite que ChatGPT explore tu código con comandos de shell (===RUN===) y proponga ediciones de archivos (===FILE===).

git clone https://github.com/abdallhMoukdad/chatgpt-browser-agent.git
cd chatgpt-browser-agent
npm install
node chatgpt.js --login   # login único
node agent.js             # bucle de agente autónomo

⚠️ Advertencia de seguridad crucial

Todas estas herramientas otorgan a un modelo de IA control directo sobre tu sistema de archivos y tu shell. Esto significa que, en teoría, el modelo podría ejecutar comandos destructivos por error o por una alucinación.

  • Nunca las ejecutes en tu sistema principal sin aislamiento. La recomendación universal es usar una máquina virtual (VM), un contenedor (Docker/DevContainer) o, como mínimo, un directorio de proyecto aislado y sin acceso a credenciales sensibles.
  • Revisa siempre los comandos antes de que el agente los ejecute, si la herramienta lo permite.
  • No les des acceso a tus claves SSH, tokens de AWS o archivos de configuración críticos.

En resumen: Portal es la opción más equilibrada para empezar (soporta varios modelos y tiene una TUI clara), mientras que CatDesk y Forge Agent son más específicas para tareas de codificación autónoma. Cualquiera de ellas te dará el control real sobre tu PC que SenGPTR no puede ofrecerte.
