ZFS combina filesystem y volume manager. En FreeBSD lo normal es elegir Auto (ZFS) durante la instalación.

¿Por qué no está integrado en Linux mainline?

ZFS sí existe en Linux (OpenZFS), pero normalmente como módulo externo (zfs-dkms, paquetes de distro, etc.), no dentro del kernel oficial. El motivo es la licencia: el kernel Linux es GPLv2 y ZFS es CDDL; distribuir código integrado/derivado con esas licencias se considera incompatible. Por eso en Linux suele instalarse aparte, mientras que en FreeBSD está integrado de forma nativa.

Tipo de pool en la instalación

  • stripe: sin redundancia, usa toda la capacidad/suma de discos.
  • mirror: espejo, como RAID1.
  • raidz1/2/3: similar a RAID5/6 con 1, 2 o 3 discos de paridad.

Si en el instalador no elegiste mirror, probablemente elegiste stripe (el primero/sin redundancia).

Conceptos

  • Pool (zpool): grupo de discos donde vive ZFS. Ejemplo: zroot.
  • Dataset: filesystem dentro del pool. Tiene propiedades propias: mountpoint, compresión, quota, etc.
  • Snapshot: foto instantánea de solo lectura.
  • Rollback: volver un dataset al estado de un snapshot.
  • Clone: copia escribible basada en un snapshot.
  • Send/Recv: enviar y recibir snapshots para backup o replicación.

Inspeccionar el estado

# Pools
zpool status
zpool list

# Datasets
zfs list
zfs mount

# Snapshots
zfs list -t snapshot

Crear datasets

Un dataset es mejor que crear directorios sueltos cuando querés propiedades separadas.

# Crear dataset
sudo zfs create zroot/data

# Ver dónde está montado
zfs get mountpoint zroot/data

# Cambiar mountpoint
sudo zfs set mountpoint=/data zroot/data

# Crear dataset con propiedades
sudo zfs create -o compression=lz4 -o quota=20G zroot/data/proyectos

Propiedades útiles

# Ver propiedades
zfs get compression,quota,atime,mountpoint zroot/data

# Activar compresión (recomendado)
sudo zfs set compression=lz4 zroot

# Cuota y reserva
sudo zfs set quota=50G zroot/home/esotericwarfare
sudo zfs set reservation=10G zroot/data

# Desactivar atime si querés menos escrituras
sudo zfs set atime=off zroot

Snapshots y rollback

Esto es lo que ext4 no trae nativo: volver atrás un filesystem completo al instante.

# Crear dataset de prueba
sudo zfs create zroot/tmp/zfs_demo
echo "version 1: datos importantes" > /tmp/zfs_demo/nota.txt

# Snapshot antes del desastre
sudo zfs snapshot zroot/tmp/zfs_demo@antes_del_desastre
zfs list -t snapshot -r zroot/tmp/zfs_demo

# Simular desastre
rm -f /tmp/zfs_demo/nota.txt

# Rollback instantáneo
sudo zfs rollback zroot/tmp/zfs_demo@antes_del_desastre
cat /tmp/zfs_demo/nota.txt
# -> version 1: datos importantes

# Limpiar
sudo zfs destroy zroot/tmp/zfs_demo@antes_del_desastre
sudo zfs destroy zroot/tmp/zfs_demo

Ver diferencias

# Diferencias entre snapshot y estado actual
sudo zfs diff zroot/data@antes_del_cambio zroot/data

Backup y replicación

zfs send/recv replica snapshots, ideal para backups incrementales.

# Backup local a otro pool
sudo zfs snapshot zroot/data@backup-2026-11-26
sudo zfs send zroot/data@backup-2026-11-26 | sudo zfs recv backup/data

# Incremental
sudo zfs snapshot zroot/data@backup-2026-11-27
sudo zfs send -i @backup-2026-11-26 zroot/data@backup-2026-11-27 | sudo zfs recv backup/data

Scrub e integridad

ZFS usa checksums para detectar corrupción. El scrub lee los datos y verifica integridad. Con redundancia (mirror/raidz), puede reparar bloques corruptos automáticamente (self-healing).

# Iniciar scrub
sudo zpool scrub zroot

# Ver progreso/estado
zpool status -v zroot

Clones escribibles instantáneos

Un clone es una copia escribible de un snapshot: se crea en segundos y solo consume los bloques que cambian (CoW). Útil para probar cambios riesgosos.

sudo zfs snapshot zroot/data@base
sudo zfs clone zroot/data@base zroot/data-test

# Trabajá en zroot/data-test; zroot/data queda intacto
sudo zfs destroy zroot/data-test
# Si el snapshot tiene clones, primero destruí los clones o usá -R con cuidado

Boot environments (FreeBSD)

Antes de actualizar el sistema podés crear un entorno booteable y volver atrás desde el loader si algo falla. Esto no es nativo en ext4.

sudo bectl create antes-upgrade
sudo bectl list

# Actualizás/pruebas cambios...

# Si algo sale mal, activar el entorno anterior
sudo bectl activate antes-upgrade
sudo reboot

Compresión transparente

Se activa por dataset/pool y las apps no necesitan cambios. lz4 es rápido; zstd suele comprimir más.

sudo zfs set compression=zstd zroot
zfs get compression,compressratio zroot

Cifrado nativo por dataset

ZFS puede cifrar datasets individuales, con claves/propiedades por dataset.

sudo zfs create -o encryption=on -o keyformat=passphrase zroot/secretos
# Al montar/bootear según configuración, pedirá cargar la key
sudo zfs load-key zroot/secretos
sudo zfs mount zroot/secretos

copies=2 (redundancia extra en un solo disco)

Guarda copias adicionales de bloques seleccionados. Ayuda ante sectores malos, pero no reemplaza un mirror.

sudo zfs set copies=2 zroot/important
zfs get copies zroot/important

Comandos peligrosos

  • zfs destroy borra datasets/snapshots; no hay papelera.
  • zpool destroy borra el pool completo.
  • zfs rollback descarta cambios posteriores al snapshot.

Antes de destruir, revisá con zfs list -r -t all nombre.

Resumen

zpool status                  # estado del pool
zfs list                      # datasets
zfs snapshot pool/ds@nombre   # snapshot
zfs rollback pool/ds@nombre   # volver atrás
zfs clone snap pool/ds        # clone escribible
zfs send/recv                 # replicar
zpool scrub pool              # verificar integridad
bectl create/activate         # boot environments
