Demo: cómo un wrapper publicitario te roba la URL al compartir

Este post nace de un caso real. Mi mamá estaba leyendo La Nación en Chrome, tocó ⋮ → Compartir y lo que mandó por WhatsApp no fue la URL de la nota, sino esta:

https://safedamageykwg.com/6fe35ff71252480899bd6ca59cb69d4f?...

Aclaración importante (para no repetir el error): no fue que haya tocado un banner publicitario dentro de la nota. El navegador mostraba la página de La Nación, pero la barra de direcciones apuntaba a safedamage..., no a lanacion.com.ar. Como el menú ⋮ → Compartir del navegador toma la URL que está en la barra, compartió esa dirección y no la de la nota. Para ella estaba mandando la noticia; para el destinatario llegó un link de publicidad.

El dominio es raro, no aparece en buscadores y fue registrado tres días antes. Al abrirlo desde otro lugar, redirige (307) a una tienda de ropa. Pero al pedirlo con el Referer de La Nación, el servidor devuelve HTTP 200 con la nota real:

Gabriel Batistuta hospitalizado tras emboscada en Reconquista… — LA NACION

Qué es esto, con nombre

No es un virus, ni un gusano, ni un troyano. Tampoco es phishing clásico (no te pide claves). Es una combinación de tres cosas:

Técnica Qué hace
Cloaking por Referer/User-Agent El servidor sirve un contenido distinto según quién visita y desde dónde.
URL masking / wrapper El contenido se muestra dentro de un iframe o proxy, pero la barra sigue con la URL del anunciante.
Secuestro del share intent El botón “Compartir” del navegador usa location.href, o sea la URL de la barra, no la del iframe.

En términos de seguridad es un dark pattern: no infecta, pero está diseñado para engañar sobre qué enlace se está compartiendo. En términos publicitarios es atribución agresiva: el anunciante se asegura de que la URL que circule sea la suya, con todos sus parámetros de seguimiento (fbclid, ad_id, pixel, utm_*).

Cómo funciona la cadena real

  1. Un sitio (La Nación) vende espacios publicitarios a una red (Meta Audience Network, por ejemplo).
  2. El anunciante (la tienda de ropa) crea una campaña con parámetros de tracking.
  3. Entre el sitio y el anunciante se inserts un redirector de clics: safedamageykwg.com. No es la tienda ni el diario: es el contador de clics.
  4. El servidor del redirector mira la cabecera Referer y el User-Agent.
  5. Si detecta que viene de un navegador con referencia del diario, sirve la nota dentro de un iframe/proxy y deja su propio dominio en la barra.
  6. Si no hay referencia (un curl, un escáner, o alguien que abre el link después), responde 307 y manda a la tienda.

En pseudo-código:

if (referer) {
  servirPaginaConNoticiaDentroDeIframe();   // HTTP 200, barra = dominio tracker
} else {
  redirect307('https://www.renovatuvestidor.com/producto/...');
}

Esto último es lo que se llama cloaking: una página muestra una cosa a los usuarios “reales” y otra a bots, escáneres o visitantes sin contexto. Acá se usa para publicidad, pero la misma idea es la que usan muchas páginas maliciosas para esconderse de los analizadores.

Por qué “Compartir” manda la URL equivocada

El navegador no sabe qué hay dentro del iframe. Para él:

  • la pestaña tiene una URL: location.href → https://safedamageykwg.com/...
  • el contenido del iframe es otro documento, con otra URL, inaccesible desde arriba si es cross-origin.

Cuando tocás ⋮ → Compartir, Chrome usa la URL de la pestaña. Lo mismo pasa con la Web Share API:

await navigator.share({ title: 'Noticia', url: location.href });

Si el wrapper puso su propia URL en la barra, location.href es la del wrapper. El usuario ve la nota, pero comparte el tracker.

Demo 1: solo cliente (abrir y probar)

Guardá esto como demo.html y abrilo en un navegador. Es autocontenido.

<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <title>Demo: wrapper con URL enmascarada</title>
  <style>
    body { font-family: system-ui, sans-serif; margin: 0; background: #111; color: #eee; }
    header { padding: 12px 16px; background: #222; border-bottom: 1px solid #444; }
    code { color: #7fdbff; }
    iframe { width: 100%; height: 70vh; border: 0; background: #fff; color: #111; }
    button { padding: 10px 14px; margin: 8px 4px; cursor: pointer; }
    #log { padding: 16px; font-family: monospace; white-space: pre-wrap; }
  </style>
</head>
<body>
  <header>Barra: <code id="bar"></code></header>

  <iframe id="frame"
    srcdoc="
      <h1>Gabriel Batistuta hospitalizado tras emboscada en Reconquista</h1>
      <p>Esta es la nota que el usuario cree que está leyendo.</p>
      <p>El contenido viene del iframe, no de la URL de arriba.</p>
    ">
  </iframe>

  <button id="share">Compartir (navigator.share)</button>
  <button id="copy">Copiar URL</button>
  <button id="inspect">Ver las dos URLs</button>
  <div id="log"></div>

  <script>
    history.replaceState({}, '', '/ad-tracker-demo/noticiaBatistuta');

    const bar = document.getElementById('bar');
    const frame = document.getElementById('frame');
    const log = document.getElementById('log');

    const urlDeLaBarra = () => location.href;
    const urlDelContenido = () => frame.contentWindow.location.href;

    bar.textContent = urlDeLaBarra();

    document.getElementById('share').addEventListener('click', async () => {
      const url = urlDeLaBarra();
      if (navigator.share) await navigator.share({ title: 'Noticia', url });
      else log.textContent = 'Copié: ' + url, navigator.clipboard.writeText(url);
    });

    document.getElementById('copy').addEventListener('click', () => {
      navigator.clipboard.writeText(urlDeLaBarra());
      log.textContent = 'Copiado: ' + urlDeLaBarra();
    });

    document.getElementById('inspect').addEventListener('click', () => {
      log.textContent =
        'URL que ve el usuario y que se comparte:\n  ' + urlDeLaBarra() +
        '\n\nURL del contenido real:\n  ' + urlDelContenido() +
        '\n\nEl menú ⋮ → Compartir usa la primera.';
    });
  </script>
</body>
</html>

Con el botón “Ver las dos URLs” se ve el truco: lo compartido es /ad-tracker-demo/noticiaBatistuta; lo leído es el srcdoc del iframe.

Demo 2: replicar el comportamiento real con un servidor mínimo

Esto ya incluye el cloaking por Referer, que es lo que hizo el wrapper de verdad. Es un servidor Node sin dependencias, para correr en local y entender el mecanismo. No lo expongas a Internet: es solo educativo.

Guárdalo como server.js:

const http = require('http');

const ARTICLE = `<!doctype html><html><body>
  <h1>Gabriel Batistuta hospitalizado tras emboscada en Reconquista</h1>
  <p>Contenido de ejemplo: esto es lo que el usuario lee.</p>
</body></html>`;

const SHOP = `<!doctype html><html><body>
  <h1>Renova tu vestidor — Camisa Zara</h1>
  <p>Esto es lo que ve quien abre el link sin Referer.</p>
</body></html>`;

function wrapper() {
  return `<!doctype html><html><body>
    <p style="font-family:monospace">BARRA: /tracker (no /article)</p>
    <iframe src="/article" style="width:100%;height:70vh;border:0"></iframe>
  </body></html>`;
}

http.createServer((req, res) => {
  const ref = req.headers.referer || '';

  if (req.url === '/article') {
    res.writeHead(200, { 'content-type': 'text/html' });
    return res.end(ARTICLE);
  }

  if (req.url === '/shop') {
    res.writeHead(200, { 'content-type': 'text/html' });
    return res.end(SHOP);
  }

  if (req.url === '/tracker') {
    // Cloaking: con Referer sirve la nota; sin Referer redirige a la tienda.
    if (ref) {
      res.writeHead(200, { 'content-type': 'text/html' });
      res.end(wrapper());
    } else {
      res.writeHead(307, { location: '/shop' });
      res.end();
    }
    return;
  }

  res.writeHead(404);
  res.end('not found');
}).listen(8080, () => console.log('Abrí http://localhost:8080/tracker'));

Cómo probarlo

node server.js

Sin Referer (como si alguien abriera el link después):

curl -i http://localhost:8080/tracker
# HTTP/1.1 307 Temporary Redirect
# Location: /shop

Con Referer (como cuando el anuncio viene de un diario):

curl -i -e 'https://www.lanacion.com.ar/' http://localhost:8080/tracker
# HTTP/1.1 200 OK
# <iframe src="/article">...</iframe>

Si abrís http://localhost:8080/tracker directamente en el navegador, no hay Referer y te manda a la tienda. Para ver la nota en el navegador, creá una página local con un link a /tracker: el navegador enviará su propia URL como Referer y el servidor servirá el wrapper.

En el caso real, el servidor era más fino: devolvía la nota cuando el Referer era de La Nación o de Facebook, y la tienda cuando no había referencia. Cambiá if (ref) por if (ref.includes('lanacion')) para emularlo.

Cómo detectarlo en la vida real

  • Mirá el dominio en el cuadro de compartir antes de enviar. Si no coincide con el sitio que estás leyendo, es un wrapper.
  • En Chrome: clic derecho → Ver código fuente. Si ves un <iframe> con la nota, la barra está mintiendo.
  • F12 → pestaña Network: fijate si la URL principal es distinta del contenido.
  • Probá el link con curl sin Referer: si redirige a una tienda/distinto sitio, hay cloaking.
  • Usá un bloqueador de anuncios (uBlock Origin, AdGuard, NextDNS): muchos de estos wrappers ni cargan.
  • Si el mensaje llegado dice “Reenviado” pero el dominio es rarísimo, verificá por otro canal.

Resumen

No era malware. Era:

  1. una campaña publicitaria con tracking;
  2. un redirector que hace cloaking según Referer;
  3. un iframe que muestra la nota mientras la barra queda en el dominio del anunciante;
  4. el botón Compartir del navegador entregando location.href.

Mi mamá vio La Nación, compartió lo que creía que era La Nación, y WhatsApp mandó la URL del anunciante. Con iframe + location.href se entiende en 30 líneas; con un servidor y una cabecera Referer se replica completo.
