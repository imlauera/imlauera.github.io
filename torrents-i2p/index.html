1) Qué es torrentear por I2P

  • I2P es una red de anonimato de capa completa (capa enruta y I2P = “IP invisible”).
  • Los eepsites (sitios .i2p) y el tráfico solo funcionan dentro de la red I2P.
  • Un torrent por I2P descarga únicamente de peers I2P. Nada de clearnet (salvo “mixed mode”, que destruye el anonimato — no usar con el mismo cliente).
  • Kanban: los peers se descubren por DHT dentro de I2P (no pasa por trackers clearnet), por eso los .torrent de I2P suelen venir como magnet sin announce.

2) Instalar y arrancar i2pd

sudo pacman -S i2pd            # Arch: extra
sudo systemctl enable --now i2pd
curl -s http://127.0.0.1:7070/ | head     # webconsole: da 200/HTML

Puertos locales (todos en 127.0.0.1):

Puerto Servicio
7656 SAM API (lo usa qBittorrent/transmission)
4444 HTTP proxy (curl/lynx/w3m/navegador)
4447 SOCKS proxy
7070 webconsole

El router “calienta” al iniciar (genera claves, busca peers fast/stable). Los primeros ~1-3 min los eepsites pueden dar timeout, después van 200.

3) Cómo acceder a una URL .i2p

Toda URL I2P debe pasar por un proxy local del router. Nunca directo.

3.1 curl

curl -x http://127.0.0.1:4444 -sL http://tracker2.postman.i2p/
# -x = usar el proxy HTTP de i2pd ; -L = seguir redirecciones ; -s = silencioso

3.2 lynx / w3m (consola)

# vía variable de entorno:
http_proxy=http://127.0.0.1:4444 https_proxy=http://127.0.0.1:4444 lynx http://tracker2.postman.i2p/
# o directamente con -http_proxy (variante según compilación):
lynx -http_proxy=http://127.0.0.1:4444 http://torrentthing.i2p/

w3m:

w3m -http_proxy http://127.0.0.1:4444 http://torrentthing.i2p/

Tip: guardá los proxies en tu shell para no repetirlos:

export http_proxy=http://127.0.0.1:4444
export https_proxy=http://127.0.0.1:4444

3.3 Verificar que responde (receta que usé)

curl -x http://127.0.0.1:4444 -m 45 -sL -o /dev/null -w '%{http_code}\n' http://NOMBRE.i2p/
  • 200 → vivo
  • 000 → timeout (eepsite apagado o router calentando)
  • 404 → hostname resuelve pero no hay página raíz
  • 500/502 → hostname no está en el addressbook o el servidor falla

4) Dónde están los torrents en I2P

Dos tipos de sitios:

Tipo Qué es Ejemplos
Indexer web con lista de torrents/magnets para buscar y bajarse torrentthing.i2p, annas-torrents.i2p, hentai-torrents.i2p
Tracker endpoint que junta peers (muchos son “open trackers” públicos) opentracker.*.i2p, tracker2.postman.i2p

Los indexers son lo que vos buscás para encontrar contenido. Los trackers son infraestructura (a veces con panel de stats).

El addressbook (la “agenda” de eepsites)

i2pd mantiene una lista pública y actualizada de eepsites conocidos:

sudo grep -iE 'torrent|tracker' /var/lib/i2pd/addressbook/addresses.csv

Es un CSV hostname,i2p,b32. Se actualiza solo (suscripción incluida). Eso fue exactamente cómo encontré todos los trackers de este documento.

6) Consejos de privacidad

  1. No mezcles clientes: si vas a bajar por I2P, no uses el mismo cliente para clearnet al mismo tiempo (los flujos se cruzan y perdés el anonimato).
  2. qBittorrent + I2P: Opciones → BitTorrent → I2P → activá, 127.0.0.1:7656, modo solo I2P. Para transmission: máscara de peer 0x100 / SAM 127.0.0.1:7656.
  3. Los .torrent de I2P suelen ser magnet sin announce; el DHT-I2P resuelve.
  4. Descargar contenido con copyright puede ser ilegal donde vivís. Eso es tuya.
  5. Para máxima privacidad además: apagá UPnP, y usá SOLO eepsites con https:// cuando exista (pocos) — o curl --compressed para menos huella.
