Opencode me arregló el agente opencli chatgpt agent

CLI: opencli 2.0.3
Extensión de Chromium: 1.0.26 → 1.0.27

Síntoma

El comando:

opencli chatgpt agent --new true "Cual es el programa que mas ram usa en mi archlinux?"

fallaba con:

{"ok":false,"error":{"code":"COMMAND_EXEC","message":"no conversation url","exitCode":1}}

Pero opencli chatgpt ask --new true "..." sí funcionaba.

También aparecía este warning de Chromium, que es inofensivo:

ContextResult::kFatalFailure: WebGL1 blocklisted

Diagnóstico

agent no es un comando del opencli oficial: es un adaptador custom que estaba en:

~/.opencli/clis/chatgpt/agent.js

Ese adaptador tenía varios problemas:

  1. Esperaba la URL de la conversación antes de enviar el primer mensaje. Un chat nuevo no tiene URL /c/<id> hasta que se envía algo. Por eso nunca encontraba la conversación y tiraba no conversation url.

  2. Usaba el waitForChatGPTResponse oficial, que identifica la respuesta comparando el texto exacto del prompt. Con prompts largos, XML/HTML y el DOM virtualizado de ChatGPT, esa comparación fallaba y el agente quedaba esperando hasta el timeout.

  3. --timeout se usaba como límite por turno y como límite global del comando. En tareas de varios turnos, opencli cortaba el comando a los 180s aunque el agente siguiera trabajando.

  4. La respuesta final se truncaba a 140 caracteres. Por eso parecía que el agente “no ejecutaba” cuando en realidad sí había respondido; el texto completo no llegaba a la salida.

  5. El prompt permitía respuestas del tipo “voy a contar…” sin ejecutar la herramienta. Eso cortaba el bucle antes de terminar la tarea.

Cambios aplicados

Archivo modificado:

~/.opencli/clis/chatgpt/agent.js

Backup:

~/.opencli/clis/chatgpt/agent.js.bak.20261113141311

Cambios principales:

  • Enviar el primer mensaje y después esperar la URL de la conversación.
  • Reemplazar la espera oficial por waitForAgentResponse, que:
    • espera a que ChatGPT deje de generar;
    • busca la última respuesta del asistente;
    • ignora respuestas ya vistas;
    • no depende del conteo de mensajes visibles ni del texto exacto del prompt.
  • Separar los timeouts:
    • --timeout: límite global del comando (default 7200 segundos).
    • --turn-timeout: límite por respuesta del asistente (default 600 segundos).
  • Devolver la respuesta final completa, sin truncar a 140 caracteres.
  • Mejorar el prompt del agente:
    • exige bloques XML dentro de un code fence;
    • prohíbe prometer acciones sin emitir el tool_call;
    • recomienda bash para contar, sumar, filtrar o procesar salidas.

Extensión de Chromium

Se actualizó la extensión de opencli:

1.0.26 → 1.0.27

Procedimiento:

  1. Descargar el release:
cd ~/Downloads
curl -fL -o opencli-extension-v1.0.27.zip \
  https://github.com/jackwener/OpenCLI/releases/download/v2.0.3/opencli-extension-v1.0.27.zip
  1. Backup de la versión anterior:
cp -a ~/Downloads/opencli-extension ~/Downloads/opencli-extension-backup-v1.0.26
  1. Reemplazar el contenido de la extensión unpacked:
cd ~/Downloads
mkdir opencli-extension.new
unzip -q opencli-extension-v1.0.27.zip -d opencli-extension.new
mv opencli-extension opencli-extension.oldtmp
mv opencli-extension.new opencli-extension
  1. Reiniciar el Chromium de Xvfb que usa opencli:
pkill -f 'xvfb-run --auto-servernum chromium'
pkill -f 'chromium --remote-debugging-port=9222'
sleep 3
cd ~
setsid nohup xvfb-run --auto-servernum chromium \
  --remote-debugging-port=9222 \
  --disable-extensions-except=/home/esotericwarfare/Downloads/opencli-extension \
  --load-extension=/home/esotericwarfare/Downloads/opencli-extension \
  --remote-allow-origins='*' \
  >/tmp/opencli-chromium.log 2>&1 < /dev/null &
  1. Reiniciar el daemon y verificar:
opencli daemon restart
opencli doctor

Uso

Uso básico:

cd /home/esotericwarfare
opencli chatgpt agent --new true "Lista las carpetas y decime cuántas hay"

Salida legible:

opencli chatgpt agent --new true "..." -f plain

Salida para scripts:

opencli chatgpt agent --new true "..." -f json

Opciones útiles:

--new true           inicia una conversación nueva
--conversation <id>  continúa una conversación existente
--max-turns <n>      máximo de turnos de herramientas (default 30)
--turn-timeout <s>   timeout por respuesta del asistente (default 600)
--timeout <s>        timeout global del comando (default 7200)

Herramientas locales disponibles para el agente:

list_dir(path)
read_file(path)
write_file(path, content)
edit_file(path, old_string, new_string)
bash(command)
grep(pattern, path?)

No hace falta usar hermes, pi ni opencode: opencli chatgpt agent funciona solo y ejecuta las herramientas en el directorio actual.

Verificación

Se probó en el host:

  • Pregunta de RAM: respondió usando bash.
  • Conteo de carpetas en /home/esotericwarfare: ejecutó bash y devolvió el total.
  • Tarea de código: creó hello.c, lo compiló con gcc, lo ejecutó y devolvió hola mundo.
